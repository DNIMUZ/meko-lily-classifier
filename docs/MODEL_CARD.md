# Model Card — meko_lily.keras (current)

A public model card in the spirit of deep transparency: what the model is,
how it was trained, what it is good and bad at, and how to re-run everything.

## Quick facts

| Property | Value |
|---|---|
| Model file | `models/meko_lily.keras` |
| Classes | `['lily', 'meko', 'other']` |
| Backbone | MobileNetV2 (ImageNet init, `include_top=False`) |
| Input | 224 × 224 × 3 RGB |
| Head | GlobalAvgPool → Dropout(0.3) → Dense(3, softmax) |
| Trainable base | top 60 layers (stage 2) |
| Loss | Sparse categorical cross-entropy + label smoothing 0.05 |
| Quality metric | **macro_recall** (mean per-class recall, class-weight agnostic) |
| Early stopping | patience 5 on `val_macro_recall` (mode max, restore best) |
| Optimizer | Adam (head LR 1e-3, finetune LR 3e-6) |
| File size | ~9.6 MB (built-in loss, no optimizer state) |

## Training config (the tuned WSL copy, `tuned_train.py`)

| Setting | Value |
|---|---|
| Epochs cap | 20 per stage |
| Batch size | 16 |
| Seed | 42 |
| Augmentation | flip, rotation 0.12, translation 0.10, zoom 0.2, brightness 0.1, contrast 0.1 |
| Class weights | lily ≈ 24.6, meko ≈ 12.2, other ≈ 0.35 (image counts 70 / 141 / 4955, 5166 total) |
| Two stages | 1) head-only @1e-3 → 2) unlock top 60 layers @3e-6 |

> The committed `train.py` is the vanilla recipe for reproducibility;
> this run used a tuned copy kept in WSL so the repo recipe stays honest and
> unchanged. Both are fully specified above.

## Reported numbers (recent tuned run)

| Metric | Value |
|---|---|
| val_accuracy (best) | 0.994 |
| val_macro_recall (best) | 0.984 |
| Unseen Test1–7 | **5 / 7 pass** (was 3 / 7 before tuning) |

Held-out evaluation numbers (fresh 80/10/10) are regenerated by
`evaluate.py` → `models/evaluation_report.md`.

## What changed vs. the previous model (PR #9)

1. Early stopping now watches **macro_recall**, not overall accuracy — so
   "other" (4,955 images) can no longer silently dominate the stopping decision.
2. Label smoothing 0.05 — prevents over-confident softmax on the sparse `lily`.
3. Occlusion-flavoured augmentation (translation, zoom, rotation) — directly
   mimics "cat in a bag / behind a chair".
4. Finetune LR 1e-5 → **3e-6** — gentler on the tiny `lily` class.
5. Repacked with a built-in loss so the app's plain `load_model` needs no
   custom-object registry.

## Known failure modes (public honesty)

| Scenario | Behaviour |
|---|---|
| Lily in a bag (unseen) | Whole-photo card now reads Lily 0.50 (was Meko 0.99). Detector still returns 0 boxes → no crop stamp. Tier 1 targets this. |
| Edited composite (Meko+Lily) | Detector names Meko; Lily's crop read as "other cat". Tier 1/2 target this. |
| Crowd of strays | Whole-photo card can say "doubt Lily". Verdict logic change (Tier 1.3) targets this. |
| Very small / far-away cat | 224px crops lose detail; Tier 2 (320px) targets this. |

## Reproduce

```bash
# training (GPU via WSL recommended)
python train.py               # vanilla recipe
# or the tuned variant described above (WSL copy)

# honest held-out report
python evaluate.py            # -> models/evaluation_report.md

# unseen holdout on your own photos (never used for training)
python holdout_test.py models/meko_lily.keras "D:\Download\Later\New folder"
```

### Notes on data ethics
- All training photos in `data/cats/` are stripped of EXIF/GPS and capped at
  448px; raw files live only in the gitignored `data/originals/` backup.
- App photos are read once in the moment and **never saved or used to retrain**.
